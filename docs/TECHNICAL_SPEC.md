# MycoGuard 技术规格（合规重写版）

> 本文档替代原课程作业中的 `TechSpec.txt`。原稿包含"准确率 100%"、"可食用/有毒
> 绝对化判定"等表述，不符合安全工具应有的不确定性语言，已全部重构。
> 本版本的所有数字与表述均以可复现实验与统计关联为准，**不做任何绝对化断言**。

## 1. 项目定位

MycoGuard 是一个**离线优先**的蘑菇安全识别助手：把统计模型蒸馏成透明、可解释、
带不确定性量化的规则引擎，并用多模态视觉模型作为**可选**在线增强。它的输出永远
是"风险档位 + 证据充分度区间"，而不是"能不能吃"。**方向与强度分离**：档位表达
风险方向，数字只表达证据强弱，且明确标注不是安全概率。

## 2. 技术亮点

1. **逻辑蒸馏（Logic Distillation）**：用 UCI Mushrooms 数据集（8,124 样本）
   训练随机森林并做纯度扫描，把判别逻辑蒸馏为前端可离线运行的 22 性状规则引擎
   （复现脚本：`scripts/analyze_dataset.py`）。
2. **数字孪生渲染**：SVG 参数化渲染，22 项性状实时驱动蘑菇形态（侧面 + 菌褶
   底面双视图），性状录入与视觉反馈强一致。
3. **不确定性量化（核心）**：四档风险语言 `低/中/高/无法判断`；**证据充分度**以
   区间展示，校准上限 97%，永不出 100%；输入不足（< 3 项或无可判别性状）强制
   「无法判断」。证据强度与风险方向解耦——低风险档不会因此显示更高的数字，也不
   使用绿色成功样式（v3 修复，见 `docs/upgrade-notes.md`）。
4. **多模态拍照识别（模态可观测性约束）**：照片 → FastAPI 代理 → `qwen-vl-plus`
   （OpenAI 兼容、base64 data URL）→ 解析并白名单清洗性状 → 与人工观察合并后走
   **同一个**离线引擎，保证两种输入模式的风险语言一致。视觉通道**只能上报照片可见
   的性状**：`odor`（嗅觉）与 `stalkRoot`（地下，需挖出）已从提示词代码表与白名单
   移除，`_sanitize` 与前端合并层双重拦截。
5. **离线优先 + 在线增强**：`/api/health` 能力探测；后端不可用时 UI 完整可用，
   仅拍照识别与 AI 润色降级。

## 3. 模型与数据（诚实指标，已用真实数据复现）

- 数据源：UCI Mushroom Dataset（agaricus-lepiota，8,124 样本，23 列 = 1 标签 +
  22 性状）。复现脚本 `scripts/analyze_dataset.py` 已在真实 CSV 上跑通，证据文件
  `distilled_rules.json` 入库。
- 预训练：随机森林（300 棵树，8:2 划分，seed 42）。
- **实测留出集准确率：100.00%（测试集 n=1625）**——该数据集近线性可分，几乎所有
  模型都能拿到这个数，因此它**几乎不携带信息**，不构成野外识别能力证据。此处仅
  作为已入库证据（`distilled_rules.json`）的附注记录，不再作为首要指标。
- **首要安全指标（真引擎回放全部 8,124 行，`npm run eval:safety`）**：
  - **假安全（有毒样本判为低风险）：0 / 3,916 = 0%**（判为低风险或无法判断者同样
    为 0）。这是本项目最值得引用的数字。
  - 代价：可食样本被判高风险 **370 / 4,208 = 8.79%**，二分类准确率 **95.45%**；
    若把「中风险」也计为警报（UI 确实会给出警示色调），则 **71.86%** 的可食样本
    被示警、准确率 62.78%。引擎是用过度示警换来的零假安全。
  - 单性状 `odor` 查表基线（`c f m p s y` → 警报）：准确率 **98.52%**、假警报 0%，
    但漏掉 **120 / 3,916 = 3.06%** 有毒样本——**基线在准确率上胜过引擎，在假安全
    率上不如引擎**。两者都如实报告。
  - 注意：该回放与权重蒸馏使用同一份数据，属**样本内**评估，不能外推到真实野外。
- 特征重要性（实测，随机森林 Gini importance）：
  `odor 0.161 · gill-color 0.112 · gill-size 0.111 · spore-print-color 0.093 ·
  ring-type 0.070 · population 0.064 · stalk-root 0.060 · bruises 0.052`。
- 100% 纯度分支（全数据集单类分支，实测）：
  - 气味：`f`→高风险(n=2160)、`s`→高风险(n=576)、`y`→高风险(n=576)、
    `p`→高风险(n=256)、`c`→高风险(n=192)、`m`→高风险(n=36)；`a l`→安全类
    （n=400/400）；
  - 孢子印：`r`（绿色）→ 高风险类（n=72）；`b o u y` → 安全类（n=48 各）；
  - 菌褶颜色：`b` → 高风险类（**n=1728**）、`r`→高风险(n=24)；`e o`→安全类
    （n=96/64）；
  - 菌环类型：`l` → 高风险类（n=1296）、`n`→高风险(n=36)；`f` → 安全类（n=48）；
  - 种群：`a n` → 安全类（n=384/400）；菌柄根：`r` → 安全类（n=192）；
  - 菌环数量：`n` → 高风险类（n=36）；菌环以上颜色：`b`→高风险(n=432)、
    `c`→高风险(n=36)、`y`→高风险(n=8)、`e g o`→安全类；生境：`w`→安全类(n=192)。
  - 其余（菌盖中央凸起 72.5%、路径生境 88.1%、窄菌褶 88.5% 等）按风险率加权。
- 规则转化（均为**数据集内的统计关联**，非绝对法则；每条规则 detail 标注支持
  样本数 n）：
  - 规则 A：气味 `f p c y s m` → critical 强风险信号（权重 6.0，纯度分支）。
  - 规则 B：孢子印绿色 `r` → critical 强风险信号（权重 5.5）。
  - 规则 C：其余可判别性状按 Gini 重要性 + 风险率分配正负权重（v2 共 20+ 条）；
    `pScore − eScore` 映射风险档位。**v2 修复了原引擎两个数据缺口**：菌褶颜色
    （重要性第 2）与菌环类型（第 5）此前零权重，现已加入。
  - 安全锚点（`a l` 气味 +3.5、`a n` 种群 +3.0、`r` 菌柄根 +3.5 等）仅作统计
    参考，绝不构成"可食用"结论。

## 4. 不确定性量化公式

**证据充分度（evidence strength）**——衡量"标本被观察得有多充分"，不是安全概率：

```
coverage    = n / 22                                   # 已观察性状占比
ruleSupport = clamp((命中规则数 − 3) / 3, 0, 1)         # 3 条是方向性判断的门槛
mixed       = pScore > 0 且 eScore > 0（且未命中 critical） # 两侧信号互相抵消
raw      = 0.50·coverage^1.2 + 0.25·ruleSupport + (critical ? 0.15 : 0)
           + 0.02 − (mixed ? 0.08 : 0)
strength = clamp(raw, 0.02, 0.97)
若 riskLevel ≠ 'high'：strength = min(strength, 0.20)     # 非高风险档显示上限
相对半宽 relHalf = clamp(0.9 − coverage, 0.15, 0.9) × (critical ? 0.6 : 1)
interval = [ strength − strength·relHalf , strength + strength·relHalf ] ∩ (0, 0.97]
```

**关键不变量（有回归测试，含全 8,124 行穷举验证）**：

1. 公式中不含 `Δscore` 的符号与大小——**方向不影响证据强度**，因此低风险档绝不会
   因为"越安全"而拿到更高的数字（这正是原 `|Δscore|` 公式的缺陷）。
2. 非 `high` 档显示值上限 0.20——**全应用最长的证据条永远不会属于读起来最安全的
   那个档位**；低风险内部仍按覆盖度区分（3 性状 7% vs 7 性状 20%）。
3. 冲突信号**扣分而非加分**：同一组性状若两侧信号互相抵消（mixed），其证据强度
   低于信号一致时——否则会出现"越拿不准越自信"。
4. 强制 `unknown` 恒为最小值（4%，区间 [2%, 18%]）。

低风险档在 UI 上使用中性色（无对勾、无绿色），数字旁明确标注"不是安全概率"。

档位映射（方向，不变）：`critical → high`；`Δscore ≥ 4 → high`；`Δscore > 0 →
medium`；`Δscore ≤ −3 → low`；其余 → `medium`。`n < 3` 或可判别性状为 0 →
**unknown**（`incomplete=true`，区间 [0.02, 0.18]，证据强度 0.04——**低于任何
方向性判断**，保证"信息不足"永远是屏幕上最弱的数字）。

> v3 修复记录：原公式为 `point = 0.40 + 0.30·(n/22) + 0.22·min(1,|Δscore|/8)`，
> 因使用 `|Δscore|`，**风险越低数字越高**（实测：3 性状低风险 54%、7 性状锚点组合
> 72%、22 性状全观察 92%），再配上绿色对勾与 0–100% 刻度，极易被读成"92% 可以吃"。
> 详见 `docs/upgrade-notes.md`。

### 4.1 视觉 × 规则双通道证据融合（拍照模式）

视觉模型的 `modelConfidence` 是对**物种猜测**的置信度，属于不同范畴，**不再加权
进风险/证据数字**，也**不得收窄区间**——照片是额外但不必然可靠的通道，不能买到精度：

```
gap = |engine.strength − modelConfidence|
  < 0.12  → agree    （双通道互证 → 区间不变）
  0.12–0.30 → partial（区间不变）
  > 0.30  → disagree （双通道分歧 → 区间 ×1.2 放宽，并在结果页标注）

strength' = engine.strength                  # 不变
interval' = [strength' − margin', strength' + margin'] ⊂ (0, 0.97]，factor ∈ {1, 1.2}
```

**只允许放宽**：一致（agree）是 no-op。原实现一致时 ×0.85 收窄，实测会让低风险档
从 "7% – 33%" 变成 "9% – 31%"——即一个可选模型对"物种"的自评让读起来最安全的结论
显得更确定，属于同一类范畴错误。档位（`riskLevel`）在任何情况下都不被视觉通道改变。

边界：无视觉 / `modelConfidence=0` → 保持引擎区间（一致性标记 `n-a`）；
引擎为 `unknown` 时，再自信的模型也不能"挽救"证据不足（一致性 `partial`）。
结果页展示一致性徽章（一致/部分一致/存在分歧/未提供有效信息），分歧时额外提示
"区间因双通道分歧加宽"。

### 4.2 离线专家解读（不弱于原版 Gemini 体验）

原版调用 Gemini 生成解释文本；v2 改为**确定性离线生成**（`src/engine/expert.ts`）：
按风险档位给出真菌学口吻的段落 + 列出已观察性状与命中规则（含严重度）+ 强制
安全句"严禁在未经过线下专业鉴定前食用野生真菌"，全程零网络、可测试。

### 4.3 示例场景（解决 22 个下拉的门槛）

`src/engine/scenarios.ts` 内置 5 个教学场景一键填充：大青褶伞组合（→高）、
鸡油菌形态（→低）、毒蝇伞外观（→无法判断，演示不确定性）、混合信号（→中）、
信息不足（→无法判断，演示输入门槛）。每个场景均有数据完整性 + 引擎档位测试。

## 5. 安全与合规设计

- **密钥**：只存在于后端环境变量 / 父级 `projects/.env`（支持 UTF-8 BOM）；
  `Settings.__repr__` 脱敏；前端零密钥。
- **代理**：浏览器只与自有 FastAPI 通信；上游失败返回 502，视觉未配置返回 503
  并附带 `offline: true`。
- **图片**：类型白名单（jpeg/png/webp）、8MB 上限、Pillow 重编码剥离 EXIF 元数据、
  最长边 1024px。
- **模型输出清洗**：视觉模型 JSON 只保留白名单性状码；confidence 夹取到 [0,1]；
  非法 JSON → 502（不崩溃）。
- **模态可观测性（v3）**：`NON_VISUAL_TRAITS = {odor, stalkRoot}` —— 照片无法观察
  的性状不出现在提示词代码表中（仅以"禁止上报"的形式被点名），也不在
  `TRAIT_VOCAB` 白名单内；模型若仍然返回，`_sanitize` 丢弃并在 `warnings` 中说明，
  前端 `dropNonVisualTraits` 再拦一次（`src/__tests__/modality.test.ts` 直接读
  `vision.py` 交叉校验两侧白名单，防止再次漂移）。手工录入不受限制。
- **免责声明**：`DISCLAIMER_TEXT` 为单一事实来源，结果页显著横幅 + 页脚常驻；
  测试断言其存在与措辞。
- **语言红线**：引擎输出禁止"可食用/有毒/无毒/能吃"等绝对化词（单元测试断言）；
  低风险档禁止出现绿色成功样式与"安全概率"式读数（DOM 级测试断言）。

### 5.1 `/api/analyze` 契约变更（v3，显式记录）

本任务的验收标准要求"视觉通道不得上报照片无法观察的性状"，这条要求与
"不改变后端 API 契约形态"这一非目标**存在冲突**。处理方式是**记录偏离并给出理由**，
而不是悄悄改掉、也不是放弃安全要求。

- **形态未变**：`{status, species_guess, confidence, traits, notes, warnings}`
  的键与类型完全一致；`app/tests/test_api.py` 原有断言未修改。
- **值域收窄**：`traits` 不再可能包含 `odor` / `stalkRoot`——照片无法建立这两个
  性状（嗅觉属于另一模态；菌柄根部在地下、需挖出）。这是**收窄而非放宽**：契约变得
  更真实，而不是更宽松。
- **`warnings` 语义变化**：由恒为 `[]` 变为真实通道，报告模型上报过、但被清洗层
  丢弃的非视觉性状。用户因此能看到"模型在幻觉"这一信息，而不是被静默忽略。
- 两侧护栏：`app/tests/test_vision_modality.py`（后端）+
  `src/__tests__/modality.test.ts`（前端，并解析 `vision.py` 交叉校验白名单）。

**优先级裁定**：安全（照片通道不得伪造嗅觉读数）高于"契约形态零变化"这一内部约束。
为便于后续评审复核，该裁定同时记录在本文件与 `docs/upgrade-notes.md`。

## 7. 已知限制

见 README「Known limitations」——包括：UCI 数据集的统计偏置（毒/可食各半，
与现实野外分布不同）、0/3916 假安全率是**样本内回放**属性而非野外验证、视觉模型
仅报告可见性状（气味/菌柄根部被白名单与清洗层双重拒绝）、知识库为教育级规模、
规则权重未在真实野外样本上验证等。
